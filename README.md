# Hypernova 1/6-Scale Prototype: Control Software

Source: `Hypernova 1 6-Scale Prototype Software & Integration Plan.pdf` (in this repo). This README is the working brief for Claude. Read it at the start of a session and continue from the **Current focus** section.

## Goal

Firmware on an ESP32 that turns RC or Bluetooth input into a **steering-servo angle** and a **drive-motor throttle**, with safe failsafes. Target: car holds **3 mph and stops on e-stop by Dec 4**. Most of the work is bench work on 5V/3.3V parts, so it can start before the battery pack exists.

Software owns: ESP32 firmware, steering, throttle, failsafe logic.
ECE owns: 10S Li-ion pack (37V nominal, 42V full), BMS, cells, spot-welding, power bus, buck converter, solar charge path.

## Hardware touchpoints

| Part | Role | Software interface |
|---|---|---|
| AITRIP ESP32 DevKit (30-pin) | Main controller | All firmware (2 spares for bench) |
| ANNIMOS 150KG servo | Steering | 50 Hz PWM, about 500 to 2500 µs |
| 40A RC ESC (3A UBEC) | Drive motor controller | Servo-style PWM, 1000 to 2000 µs |
| LA8308 brushless motor | Drive motor (candidate) | None directly; the ESC runs it |
| A2212 1000KV + 30A ESC | Bench-test rig | Same ESC protocol; run on bench supply or 3S only |
| BTS7960 H-bridge | Brushed motor only | RPWM/LPWM + direction; unused if brushless |
| HC-06 | Bluetooth module | **Not needed**, the ESP32 has Bluetooth built in |

## Open risks to verify (do not treat as fact)

These came from search listings, not spec sheets. Do not write code that assumes any of them is resolved.

1. The 40A ESC may be 2 to 6S (about 25V max), but the pack is 10S at 42V. The ESC must be rated for 10S. This is the main schedule risk; a replacement is needed before Nov 6 if it fails.
2. The A2212 is a 2 to 4S drone motor. Bench use only.
3. The servo may need 10 to 12.6V, not 5 to 6V. It needs its own 12V rail from the buck. The ESP32 needs a separate 5V rail.
4. LA8308 KV (90 to 205 by variant) is unconfirmed, and it may be too large for the car.
5. BMS, cells, solar charge controller, fuse, e-stop switch, and RC TX/RX may not be ordered.
6. Scale is unclear: 1/6 (ECE doc) or 1/16 (brief).

Open questions for the ECE lead are checkboxed in section 7 of the PDF. Ask the user for answers rather than guessing.

## Rules for all code and bench work

- **Safety logic is independent of input source.** Swapping serial for BLE or RC input must not touch the failsafe code.
- Signal-loss timeout: motor goes to neutral within **0.5 s** of lost input. Inputs must repeat at least every 0.5 s.
- Slowing down is immediate; only speeding up is ramped.
- Enforce min/max pulse limits in code (steering end stops, throttle cap). Start narrow, widen after measuring.
- E-stop is a normally-closed switch to GND on `INPUT_PULLUP`. Open or broken wire means stop.
- Arming sequence at boot (ESC at minimum throttle, about 3 s) before any command is accepted. Add a watchdog.
- Failsafe checks must keep running while input is read: non-blocking code, timers, or FreeRTOS tasks. No blocking `delay()` outside setup.
- Common ground across the ESP32, ESC, servo supply, and receiver.
- Never power the ESP32 from USB and the car rail at once.
- Wheels off the ground for every first power-on. Propeller off and motor clamped for bench motor tests.
- BLE, not Bluetooth Classic (iPhones cannot use Classic).
- Out of scope this semester: PID, CAN bus, solar MPPT. Note them in the handoff doc instead.

## Starter firmware (untested on hardware)

One file, `ESP32Servo` library. Behavior the first version must have:

- Pins: steer = 18, ESC = 19, e-stop = 27 (check against the board pinout).
- `STEER_MIN_US` 1000, `STEER_MAX_US` 2000 (narrow until end stops are found).
- `ESC_STOP_US` 1000, `ESC_MAX_US` 1300 (1500 = stop if the ESC is bidirectional; 1300 caps first tests).
- `RAMP_US_PER_TICK` 5, `TICK_MS` 20, `TIMEOUT_MS` 500.
- Serial commands: `s1500` sets steering, `t1100` sets throttle. Each command resets the timeout.
- If e-stop is open or the command is stale, target throttle goes to `ESC_STOP_US`.
- Attach: steering 500 to 2500 µs, ESC 1000 to 2000 µs, both at 50 Hz.

## Project files

Only four things here are hand-written. Everything else is generated by the tools.

| File | What it is |
|---|---|
| `src/main.cpp` | The firmware. Everything the ESP32 does is here. |
| `src/config.h` | Settings: pin numbers, servo and throttle limits, timeouts. Change numbers here, not in `main.cpp`. |
| `platformio.ini` | Project setup: board is ESP32 DevKit, framework is Arduino, needs the `ESP32Servo` library. |
| `README.md` | This file. |

Generated, safe to ignore: `.pio/` (compiled output and downloaded libraries, rebuilt on every build), `.vscode/` (VS Code PlatformIO extension settings), `.git/` (version history). `.gitignore` keeps `.pio/` and `.vscode/` out of Git.

### Language

The code is C++ in the Arduino style. `setup()` runs once at power-on, then `loop()` runs over and over. Most of it reads like plain C (`int`, `if`, `char` arrays, `atoi()`). The C++ parts are the servo library objects (`Servo steer, esc;`, `steer.writeMicroseconds(...)`) and `constexpr` constants in place of `#define`.

### How `main.cpp` is laid out

1. **Input layer:** reads serial commands (`s1500` steering, `t1100` throttle, `w` toggle steering sweep). BLE or RC input replaces this on Oct 23.
2. **Safety layer:** forces throttle to stop if no command for 0.5 s, the e-stop is open, or the ESC is still in its 3 s arming period. Does not depend on the input source.
3. **Output layer:** writes the servo and ESC pulses every 20 ms (50 Hz). Throttle ramps up gradually and cuts immediately.

## Build, flash, and talk to the board

PlatformIO is installed through the VS Code extension. Its command-line tool is at `~/.platformio/penv/bin/pio` (not on the shell PATH). The VS Code PlatformIO toolbar buttons do the same things.

```
~/.platformio/penv/bin/pio run                                          # compile
~/.platformio/penv/bin/pio run -t upload                                # compile and flash over USB
~/.platformio/penv/bin/pio device monitor -p /dev/cu.usbserial-0001     # serial monitor (Ctrl+C to quit)
```

On boot the board prints `ready (arming 3s)`. Type commands in the monitor and press Enter.

Status (Oct 16): firmware compiles (21.7% flash, 6.7% RAM), flashed to an ESP32 DevKit over USB, and boots. Servo and ESC outputs have not been tested on hardware yet.

Throttle stays at stop until pin 27 is connected to GND (the e-stop input reads an open pin as "stop"). Steering is not affected by the e-stop.

## Servo bench test

### Wiring

```
                 ESP32 DevKit                      Servo (3-wire plug)
              ┌──────────────┐
              │        GPIO18├──────────────────── Signal (orange / yellow / white)
              │           GND├───────┐
              └──────┬───────┘       │
                  USB to Mac         ├──────────── Ground (brown / black)
                                     │
          External supply   (−) ─────┘
          at servo spec V   (+) ────────────────── Power (red)
```

- **Signal:** servo signal wire to GPIO18. The ESP32's 3.3 V signal drives most servos directly.
- **Power:** servo red wire to a separate supply at the servo's rated voltage. **Never** power the servo from the ESP32's 3V3, 5V, or VIN pins: a 150 kg servo draws several amps and will brown out or damage the board.
- **Ground:** servo ground, supply negative, and an ESP32 GND pin all tied together. Without the shared ground the signal has no reference and the servo jitters or does nothing.
- **Voltage is unconfirmed** (open risk 3: may need 10 to 12.6 V, not 5 to 6 V). Read the label or spec sheet before powering it. On a bench supply, set the voltage first and a current limit of about 2 to 3 A.
- ESP32 stays on USB power only for this test.

### Steps

1. Wire signal and ground first, power last. Servo horn free with nothing attached, so it can't bind.
2. Open the serial monitor. Turn on the servo supply.
3. `s1500`: servo moves to center.
4. Small steps: `s1400`, `s1600`, then `s1300`, `s1700`, and so on. Stop at any step where the servo buzzes or strains: that is a mechanical end stop. Note the last quiet value on each side.
5. `w`: continuous sweep between `STEER_MIN_US` and `STEER_MAX_US` (1000 to 2000). Should be smooth with no jitter. `w` again stops it.
6. Put the measured end stops into `STEER_MIN_US` / `STEER_MAX_US` in `config.h`, with a small margin, and re-flash. Do this again on the chassis (Nov 6), since the steering linkage will limit travel further.

If the servo jitters: check the shared ground first, then the supply current limit.

## First bench test order

1. ESP32 on USB only. Confirm 50 Hz on both signal pins (logic analyzer or scope).
2. Servo on its own supply at its spec voltage, grounds tied. Send `s1500`, then small steps. Stop if it buzzes at an end stop.
3. A2212 + 30A ESC on bench supply or 3S, propeller off, motor clamped. Power the ESC after the ESP32 has booted.
4. Wait for arming beeps, send `t1050`, raise in small steps.
5. Stop sending commands: motor must cut within about 0.5 s.
6. Open the e-stop circuit: same result.
7. Only then move to the chassis, wheels off the ground.
